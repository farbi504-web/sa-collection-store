# SA Collection: متجر + لوحة تحكم

مشروع جديد من الصفر (Next.js 14 + Prisma + PostgreSQL/Neon + Vercel Blob). لا يعتمد على أي ملف من الإصدارات السابقة.

## حالة التحقق (اقرأها أولاً)

| الفحص | النتيجة |
|---|---|
| صياغة كل ملفات TypeScript (55 ملفاً) | سليمة |
| وجود كل الملفات المستورَدة | سليمة |
| `npm install` / `tsc` / `next build` | **لم تُنفَّذ**: الشبكة معطّلة في بيئة الكتابة |
| تشغيل المتجر واللوحة على قاعدة بيانات حقيقية | **لم يحدث** |
| اختبارات آلية | **غير موجودة** |

يعني هذا أن الكود مكتوب بعناية لكنه **غير مُجرَّب**. توقّع احتمال أخطاء أنواع أو بناء عند أول `npm run build`. أرسل لي نص الخطأ وأصلحه.

## ما هو مبني فعلاً

**المتجر**
- الرئيسية: شريط إعلانات، هيدر (قائمة، شعار، بحث، سلة)، بانر بشرائح (صور حاسوب/هاتف، تبديل تلقائي ويدوي)، New Collection، Our Favorites، لافتة الرضا، الآراء قبل المجتمع، Join Our Community، الزخرفة النباتية أسفل اليسار، فوتر أسود بخمس خانات وفواصل بيضاء.
- المتجر: بحث، تصفية بالقسم والمقاس واللون، ترتيب بالسعر، ترقيم صفحات.
- صفحة المنتج: معرض صور، اختيار مقاس ولون مع تعطيل التركيبات النافدة، SEO وبيانات Product منظمة.
- السلة محفوظة في المتصفح. الدفع عند الاستلام فقط.
- الطلب: الأسعار والمخزون والتوصيل تُحسب في السيرفر من قاعدة البيانات، لا من المتصفح. خصم المخزون ذري داخل transaction ولا ينزل تحت الصفر. مفتاح منع التكرار يمنع طلبين من ضغطتين أو إعادة إرسال.
- تتبع الطلب برقم الطلب + الهاتف معاً.
- صفحات نصية (`/p/اسم`).

**اللوحة (/admin)**
- نظرة عامة بأرقام حقيقية (فلاتر: اليوم، أمس، 7 أيام، 30 يوماً، هذا الشهر).
- المنتجات مع متغيرات (مخزون لكل مقاس/لون)، نسخ، أرشفة، حذف.
- الأقسام، الطلبات بثماني حالات وانتقالات مفروضة في السيرفر وسجل لكل تغيير، تصدير CSV، طباعة، اتصال وواتساب.
- المخزون: تعديل يدوي مسجَّل (قبل/بعد/السبب/المنفّذ) وحركات تلقائية. إلغاء الطلب يُرجع المخزون.
- الزبائن (مجمّعون بالهاتف)، آراء الزبائن بالموافقة، الصفحات.
- أسعار التوصيل لكل ولاية، التوصيل المجاني، حد المخزون المنخفض.
- **تصميم الموقع**: محرر لكل أقسام الرئيسية والهيدر والفوتر والألوان، مسودة ونشر وحذف مسودة، معاينة حية (حاسوب/لوحي/هاتف) لا يراها إلا المدير، نسخ سابقة مع استرجاع.
- سجل عمليات.

## غير مبني بعد (بصراحة)

- ربط Anderson الآلي: لا يوجد توثيق رسمي مؤكد، فلم أخترع مسارات. الحالة «غير مُعدّ». يُسجَّل رقم التتبع يدوياً.
- SA AI Assistant، التحليلات المتقدمة، الكوبونات، الأدوار والصلاحيات (حساب مالك واحد فقط)، مكتبة الوسائط، الإشعارات (يظهر عدد الطلبات الجديدة في القائمة فقط)، sitemap وrobots.
- سحب وإفلات الأقسام (الترتيب بأزرار أعلى/أسفل)، حسابات الزبائن والمفضلة، تعديل الطلب بعد إنشائه، تحرير العناصر على المعاينة مباشرة.
- قائمة البلديات: حقل نصي حر. القائمة الدقيقة تحتاج مصدراً موثوقاً.
- Rate limiting في الذاكرة (لكل نسخة سيرفر)، وليس عالمياً.

## قرارات تصميم مقصودة

- لا أرقام ولا آراء ولا منتجات وهمية. لافتة «97%» مخفية ومحتواها فارغ حتى تكتب نسبة تملك ما يدعمها.
- ولاية بدون سعر توصيل = غير متاحة (لا يمكن الطلب إليها) حتى تحدد سعرها.
- حقول الصور تقبل `https://` أو مسارات الموقع فقط، وألوان القالب تُتحقق بصيغة hex.
- صفحات المحتوى تُعرض كنص عادي (لا HTML) تفادياً لحقن الأكواد.

## التشغيل

1. أنشئ قاعدة على neon.tech وانسخ `DATABASE_URL` (pooled) و`DIRECT_URL`.
2. انسخ `.env.example` إلى `.env` واملأه. `AUTH_SECRET`: `openssl rand -hex 32`.
3. `npm install` ثم `npx prisma db push` ثم `npm run dev`.
4. ادخل `/admin` بالبريد وكلمة السر من `.env`.
5. من «التوصيل والإعدادات» أدخل أسعار الولايات. من «المنتجات» أضف منتجاتك بصورها.
6. من «تصميم الموقع» أضف صور البانر وروابط الشبكات ثم انشر.

## النشر على Vercel

1. ارفع المشروع إلى GitHub ثم Import في Vercel.
2. Storage ← أنشئ **Blob** وربطه (يضيف `BLOB_READ_WRITE_TOKEN`).
3. أضف المتغيرات: `DATABASE_URL`, `DIRECT_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `AUTH_SECRET`.
4. Deploy. أمر البناء ينفّذ `prisma db push` (بدون `--accept-data-loss`، فأي تغيير يحذف بيانات يتوقف بدل أن ينفّذ).
5. افتح `/api/health` للتأكد أن المتغيرات والجداول سليمة (لا يكشف أي قيمة سرية).

## متغيرات البيئة

`DATABASE_URL`, `DIRECT_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `AUTH_SECRET`, `BLOB_READ_WRITE_TOKEN`
